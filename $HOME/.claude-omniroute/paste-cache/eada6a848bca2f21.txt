============================================================
13. FILE STORAGE
============================================================

Use the existing MinIO/S3-compatible storage architecture.

Documents MUST be PRIVATE.

NEVER expose:

/uploads/documents/file.pdf

as a public URL.

Do not store sensitive documents in the frontend repository.

Do not store document binaries directly in PostgreSQL.

PostgreSQL stores metadata.

MinIO stores the actual file.

============================================================
14. STORAGE KEY
============================================================

Storage keys should be generated server-side.

Do not use the original filename as the storage key.

Recommended conceptual structure:

shops/{shop_id}/applications/{application_id}/documents/{document_id}/{safe_filename}

The exact structure may differ if the existing MinIO helper already establishes a convention.

Storage keys must prevent:

- path traversal
- collisions
- tenant leakage

============================================================

============================================================

Reject or sanitize:

..\file

============================================================
19. TRANSACTION / STORAGE CONSISTENCY
============================================================

MinIO is not part of the PostgreSQL transaction.

Handle failure safely.

Possible flow:

Upload object
↓
Create DB record

If DB fails:

Delete uploaded object.

If object upload fails:

Do not create DB record.

If practical, implement cleanup/retry behavior.

Do not claim true atomicity between PostgreSQL and MinIO.

============================================================
20. SECURE DOWNLOAD
============================================================

Documents are PRIVATE.

Users should not receive permanent public URLs.

Use short-lived signed/presigned URLs OR a secure backend streaming endpoint.

If using signed URLs:

- short expiry
- generated only after authorization
- tenant checked first
- application checked first
- document checked first

A user must never obtain a signed URL for another shop's document.
